# SYDE 블로그 — 기획 배경과 방향

> 작성일: 2026-09-19
> 성격: 인사이트 게시판을 블로그로 전환하는 **이유, 방향, 원칙, 최종 목표**를 정리한 문서. 코드 레벨의 할 일은 [구현 명세](blog-implementation.md)에 있다.
> 이전 기록: [인사이트 → 블로그 전환 UI/UX 분석](blog-conversion-ux-analysis.md) (2026-09-13 ~ 09-19 분석·작업 이력. 결정의 상세 근거가 필요할 때 참고)

---

## 1. 요약

SYDE 인사이트 게시판에는 **읽는 사람은 있지만 쓰는 사람이 없다.** 글은 전부 운영자가 만든 카드뉴스이고, 화면 구조도 그런 "완성된 발행물"에 맞춰져 있다. 그래서 일반 사용자는 이곳을 "내가 올려도 되는 곳"으로 여기지 않는다.

이 게시판을 **사이드프로젝트를 하면서 겪은 일을 누구나 가볍게 기록하는 블로그**로 바꾼다. 해프닝과 삽질기, 프로젝트 홍보, 기술 블로그, 마케팅 노하우, TIL이 모두 이곳에 쌓이게 하는 것이 목표다.

이를 위해 에디터는 velog, brunch, tistory, 네이버 블로그보다 **쓰기 쉽고, 직관적이고, 결과물이 예뻐야 한다.** 핵심 방향은 다음 세 가지다.

1. **쓰기 시작하는 데 장벽이 없다.** 제목과 본문만 쓰면 되고, 나머지는 발행할 때 고른다.
2. **알아서 된다.** 붙여넣기, 자동저장, 요약과 대표 이미지 추천처럼 작성자가 신경 쓸 일을 에디터가 대신한다.
3. **개발자와 비개발자 모두 편하다.** 기본은 보이는 대로 쓰는 편집기(위지윅)이고, 마크다운 입력·붙여넣기·불러오기와 좋은 코드 블록을 함께 제공한다.

## 2. 배경

### 2-1. 현재 상황 (2026-09-13 프로덕션 확인)

- 목록 첫 페이지의 글 18개는 **모두 공식 계정 "사이드"가 쓴 글**이다.
- 조회수는 글마다 36~838로, **독자는 이미 있다.**
- 반면 댓글이 달린 글은 18개 중 2개, 북마크는 전부 0이다.
- 썸네일은 모두 인스타그램 카드뉴스 스타일로 디자인된 이미지다.

### 2-2. 문제의 본질

기획 문서는 사용자들이 *"나는 올리면 안 되는 공간"* 이라고 오해한다고 진단했다. 이 오해는 작성자가 공식 계정뿐이라서만 생기는 게 아니다. **화면 구조가 적극적으로 그 오해를 만든다.**

- **목록**: 정사각형 썸네일 그리드라서 이미지 없는 글은 초라해 보인다. 이미지가 없으면 마스코트 이미지로 채워진다.
- **상세**: 가운데 정렬된 큰 제목과 정사각형 썸네일로, 잡지 표지 같은 격식을 요구한다.
- **작성 폼**: 한 줄 소개가 필수이고, 버튼 문구가 "등록하기"라서 심사를 받는 제출처럼 느껴진다.

그래서 **메뉴 이름만 "블로그"로 바꾸고 이 구조를 유지하면 오해는 풀리지 않는다.** 작성 화면, 목록, 상세를 모두 "가볍게 쓰는 개인 기록"에 맞게 바꿔야 한다.

### 2-3. 왜 블로그인가

- **쌓이는 기록**: 쇼케이스가 "결과물"을 보여준다면, 블로그는 그 결과물까지의 "과정"을 쌓는 곳이다. 둘이 연결되면 SYDE만의 콘텐츠가 된다.
- **프로필 전략과의 연결**: 기획 문서 2~3단계의 *"프로필 = 부캐 명함"* 전략에서, 블로그 글은 명함을 채우는 가장 자연스러운 재료다.
- **독자는 이미 있다**: 새로 모아야 하는 건 작성자다. 작성 경험이 이번 전환의 성패를 가른다.

## 3. 누가, 무엇을 쓰는가

### 3-1. 작성자

- 사이드프로젝터, 1인 개발자, 솔로프리너. **비개발자도 포함된다.**
- 주 유입 경로가 오픈채팅이라 **모바일에서 쓰는 비중이 높다.**
- 첫 작성자는 콜드 시딩으로 모은다. 대상은 쇼케이스 업보트 상위 등록자이고, 요청은 *"만들다가 있었던 일 3~5줄만 편하게 써주세요"* 다. 이들은 **재시도 기회가 없는 가장 아까운 표본**이라, 첫 작성 경험에서 이탈하면 되돌릴 수 없다.

### 3-2. 다섯 가지 글 유형

| 유형 | 모습 | 에디터·독자 화면에 필요한 것 |
|---|---|---|
| **해프닝·삽질기** | 짧고 가벼운 이야기, 스크린샷 몇 장 | 제목·본문만으로 발행, 여러 장 이미지, 이미지 없어도 어색하지 않은 목록 |
| **프로젝트 소개·홍보** | 서비스 링크, 데모 영상, 스크린샷 | 링크 카드, 유튜브, 이미지 나란히 놓기, 보기 좋은 대표 이미지 |
| **기술 블로그** | 긴 글, 코드, 단계별 설명 | 코드 강조·복사, 목차, 제목 앵커, 마크다운 붙여넣기·불러오기, 표 |
| **마케팅·그로스 노하우** | 수치, 비교, 체크리스트 | 표, 콜아웃, 형광펜, 체크리스트, 인용 |
| **TIL** | 짧은 학습 기록, 자주 씀 | 빠른 작성, 코드 블록, 태그로 모아보기 |

## 4. 다른 블로그 플랫폼과의 비교

| 플랫폼 | 강점 | 약점 | 우리가 가져올 것 / 피할 것 |
|---|---|---|---|
| **velog** | 개발자 친화 마크다운, 시리즈·태그, 우측 목차, 트렌딩 | 마크다운이 비개발자에게 높은 장벽 | 목차·코드 품질·태그·시리즈는 가져오고, 마크다운 전용 편집기는 피한다 |
| **brunch** | 여백과 타이포그래피가 아름다운 글 화면, 글쓰기에 집중하는 작성 화면 | 작가 심사제라는 진입 장벽 | 깔끔한 작성·읽기 화면은 가져오고, "심사받는 느낌"은 피한다 |
| **tistory** | 높은 자유도, 서버 임시저장, 카테고리 | 에디터가 무겁고 복잡함 | 서버 임시저장·카테고리는 가져오고, 설정이 많은 화면은 피한다 |
| **네이버 블로그** | 풍부한 컴포넌트(이미지 여러 장 배치 등), 모바일 앱 | 기능이 너무 많고 광고성 글 이미지가 강함 | 이미지 나란히 놓기는 가져오고, 기능 과잉은 피한다 |

**SYDE만의 차별점**

- **커뮤니티 안의 블로그**: 쇼케이스 프로젝트, 댓글과 반응, 작가 프로필과 연결된다. 혼자 쓰는 블로그가 아니라 읽어줄 사람이 있는 곳이다.
- **노션처럼 편한 편집**: `/` 명령, 선택하면 뜨는 서식 메뉴, 붙여넣기만 해도 알아서 되는 동작.
- **한국어·모바일 우선**: 한글 입력기(IME) 조합 처리, 16px 입력(iOS 확대 방지), 터치 크기, 모바일 전용 메뉴 위치.
- **쓰는 화면 = 읽는 화면**: 같은 서체와 여백, 같은 렌더러를 쓰는 미리보기.

## 5. 방향 — 원칙

모든 기능 결정은 아래 원칙으로 판단한다.

1. **쓰기 시작까지 장벽 0**
   필수는 제목과 본문뿐이다. 한 줄 소개, 대표 이미지, 카테고리, 태그는 발행 창에서 고르는 선택 항목이다. 작성 화면에는 쓰는 데 필요한 것만 둔다.
2. **글을 절대 잃지 않는다**
   브라우저와 서버에 두 겹으로 자동 저장한다. 다른 기기에서 이어 쓸 수 있고, 네트워크가 끊겨도 남는다.
3. **알아서 된다**
   - 글자를 선택하고 URL을 붙여넣으면 링크, 빈 줄에 붙여넣으면 링크 카드나 유튜브가 된다.
   - 마크다운은 서식으로 바뀌고, 만료되는 외부 이미지는 SYDE로 옮겨진다.
   - 한 줄 소개와 대표 이미지는 본문에서 자동으로 제안된다.
4. **기능은 숨기지 않고 발견되게**
   `/` 안내, 선택 메뉴, 단축키 도움말로 알려준다. 붙여넣기로만 쓸 수 있는 기능은 두지 않는다.
5. **쓰는 화면과 읽는 화면이 같다**
   같은 타이포그래피와 본문 폭을 쓴다. 제목 위계는 글 제목 > 제목 1 > 제목 2 > 제목 3이다. 미리보기는 실제 발행 화면과 같은 렌더러를 쓴다.
6. **모바일이 데스크톱과 동등하다**
   터치 영역 40px 이상, 입력 16px, 화면 가장자리까지 쓰는 본문. 가로 스크롤 툴바에는 더 있다는 표시를 둔다.
7. **개발자와 비개발자 모두**
   기본은 위지윅이다. 마크다운 단축 입력, 붙여넣기, 파일 불러오기를 지원한다. 코드 블록은 언어 선택, 문법 강조, 복사를 제공한다.
8. **작성자를 위축시키지 않는다**
   0인 지표는 숨긴다. 이미지 없는 글도 목록에서 자연스럽다. "등록·심사" 대신 "발행" 톤을 쓴다.

## 6. 주요 결정과 근거

| 결정 | 내용 | 근거 |
|---|---|---|
| **에디터 엔진** | Tiptap(ProseMirror)을 유지한다. 마크다운 전용 편집기로 바꾸지 않는다 | 필요한 기능이 모두 Tiptap 안에서 해결된다. 마크다운 전환은 비개발자에게 장벽이고 기존 글의 링크 카드·이미지 크기 정보를 잃는다 |
| **마크다운 모드** | 입력만 마크다운으로 받는 토글은 보류하고, 고유 작성자 20명 / 월 15건 도달 시 다시 검토한다 | 개발자 요구가 실제로 커졌을 때 기존 글과 공존하는 방식으로 얹을 수 있다 |
| **URL·메타데이터** | `/insight/` URL은 유지한다. 메뉴 이름은 "블로그"로 바꾸되, 검색용 메타 제목·설명은 2차 리네이밍(20명 / 월 15건) 때 바꾼다 | 기존 검색 인덱스와 공유 링크 보호 |
| **한 줄 소개** | 선택 입력. 비어 있으면 서버가 본문 앞 120자로 채워 저장한다 | "3~5줄만 편하게"라는 약속과 필수 입력이 충돌한다. 목록·검색·공유 미리보기가 같은 값을 쓴다 |
| **카테고리·태그** | 작성자가 발행 창에서 카테고리를 고른다(강제하지 않음). 운영자가 나중에 고칠 수 있다. 자유 태그는 글당 5개 | 쓰임새가 분명해 작성자 선택이 정확하고 목록 필터에 바로 쓸 수 있다. ⚠️ 기획 문서 6장("운영자 사후 태깅")을 이 결정으로 갱신해야 한다 |
| **서버 임시저장** | 발행 글 테이블과 분리된 초안 테이블을 둔다 | `insights`에 상태 컬럼을 넣으면 읽는 곳 8곳에 필터를 넣고 보안 정책·활동 피드 트리거도 고쳐야 한다. 하나라도 빠지면 초안이 공개된다 |
| **제목 위계** | 본문에서 제목 1~3을 모두 쓴다. 크기는 항상 글 제목이 가장 크다(데스크톱 40 > 32 > 26 > 21px) | 벨로그와 같은 위계. 본문 H1이 커 보이던 문제는 H1 자체가 아니라 스타일 설정 버그였다 |
| **목록 지표** | 목록 카드에는 조회수와 좋아요만, 0이면 숨긴다. 상세 페이지는 4개 지표를 유지한다 | 신규 작성자의 첫 글이 "0 0 0 0"으로 박제되면 두 번째 글이 나오지 않는다 (기획 문서 7장에 대한 수정) |
| **공용 에디터** | 에디터는 6곳(인사이트·쇼케이스·클럽 글·클럽 수정·모임 소개·프로필 소개)이 공유한다. 블로그 전용 기능(발행 창·분류·목차)은 인사이트에만 둔다 | 편집 품질 개선은 사이트 전체에 이득이다. 블로그 흐름은 블로그에 한정한다 |

## 7. 현재 위치 (2026-09-19)

**이미 된 것**

- **편집**
  - 문단 형식 메뉴, 텍스트 선택 서식 메뉴, `/` 명령 메뉴, 단축키 도움말
  - 링크(⌘K), 밑줄, 인라인 코드, 형광펜, 글자색
  - 체크리스트, 표, 콜아웃, 문법 강조 코드 블록
- **미디어**
  - 여러 장 이미지 업로드, 캡션·대체 텍스트
  - 링크 카드, 유튜브
- **붙여넣기**
  - URL 처리, 마크다운 변환(되돌리기 가능)
  - 노션·구글독스 서식 유지, 만료되는 외부 이미지를 SYDE로 옮김
- **작성 흐름**
  - 상단 고정 작성 바, 발행 전 미리보기
  - 브라우저 자동 임시저장과 복원(에디터 6곳), 항목별 발행 검증
- **읽기**
  - 서버 HTML 렌더링, 본문 폭 768px, 이미지 지연 로딩

**남은 큰 과제**

- **작성 흐름**: 테두리 없는 작성 화면, 발행 창, 서버 임시저장, 카테고리·태그
- **발견성**: 빈 줄 `/` 안내, 유튜브·링크 카드를 메뉴에서 넣기, 링크 편집 메뉴
- **독자 경험**: 목차, 제목 앵커, 코드 복사
- **게시판**: 글쓰기 진입점, 텍스트 우선 목록, 상세 헤더, 작가 카드, 정렬·필터, 문구 리네이밍
- **고급 편집**: 문단 드래그, 이미지 나란히 놓기, 마크다운 파일 불러오기

## 8. 최종 목표 — 작성자와 독자의 경험

### 8-1. 작성자

1. 블로그 목록에서 **"글쓰기"** 버튼, 또는 상단의 *"오늘 만들면서 있었던 일, 편하게 적어보세요"* 입력창을 누른다.
2. 테두리 없는 하얀 화면에서 **제목**을 쓰고 Enter를 누르면 본문으로 넘어간다.
3. 빈 줄에 보이는 *"'/'를 입력해 블록 추가"* 를 보고 `/`로 이미지, 코드, 표, 콜아웃, 유튜브를 넣는다.
4. 노션에서 복사한 초안이나 마크다운을 붙여넣으면 서식이 그대로 살아난다. 스크린샷 여러 장은 한 번에 들어가고, 원하면 나란히 놓는다.
5. 쓰는 동안 상단 바에는 *"저장됨 14:02"* 가 보인다. 노트북에서 쓰던 글을 지하철에서 휴대폰으로 이어 쓴다.
6. **"발행하기"** 를 누르면 발행 창이 열린다.
   - 본문 이미지 중 하나를 대표 이미지로 고른다.
   - 한 줄 소개는 비워두면 자동으로 채워진다.
   - 카테고리를 고르고 태그를 단다.
7. 발행하면 글이 목록 맨 위에 **이미지가 없어도 자연스럽게** 놓인다.

### 8-2. 독자

1. 목록은 제목, 본문 발췌, 작성자가 보이는 텍스트 중심이다. 한 화면에 4~6개 글이 보이고 카테고리로 거를 수 있다.
2. 긴 기술 글은 오른쪽 **목차**로 이동하고, 코드는 **복사** 버튼으로 가져간다. 특정 섹션을 링크로 공유할 수 있다.
3. 글 끝에서 **작가 카드와 그 작가의 다른 글**로 이어 읽고, 작가 프로필(부캐 명함)로 간다.

## 9. 로드맵

| 단계 | 시점 | 목표 | 주요 작업 |
|---|---|---|---|
| **M1. 시딩 준비** | 콜드 시딩 DM 발송 **전** | 첫 작성자가 폼 앞에서 이탈하지 않게 | 에디터 버그 수정, 테두리 없는 작성 화면과 발행 창, 한 줄 소개 선택화, "발행" 톤 문구, 글쓰기 진입점, 목록 문구. 권장: `/` 안내와 메뉴 확장, 링크 편집 메뉴 |
| **M2. 시딩 기간** | 시딩 글이 쌓이는 동안 | 유저 글이 목록에서 자연스럽고, 긴 글도 잃지 않게 | 카테고리·태그, 텍스트 우선 목록, 지표 정리, 상세 헤더, 목차·코드 복사, 작가 카드. 서버 임시저장은 보류하고 필요 신호가 보이면 시작한다 |
| **M3. 성장** | 작성자가 늘어난 뒤 | 더 풍부한 글, 발견과 재방문 | 문단 드래그, 이미지 나란히 놓기, 마크다운 불러오기, 정렬(인기순), 카테고리·태그 모아보기, "인사이트" 문구 리네이밍 |

세부 작업, 파일, 완료 조건은 [구현 명세](blog-implementation.md)를 따른다.
